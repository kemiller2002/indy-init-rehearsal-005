# NR-WORKFLOW-DIAGRAM-INTEGRATION§acceptance-scenarios

Derived from baseline requirement `WORKFLOW-DIAGRAM-INTEGRATION§acceptance-scenarios` (Acceptance scenarios). Each obligation is carried verbatim as the criterion that bears its id.

| ID | Acceptance criterion |
|---|---|
| WORKFLOW-DIAGRAM-INTEGRATION§acceptance-scenarios-O1 | Load a populated causal investigation offline; render through the actual Echelon workflow layout system without GitHub access. |
| WORKFLOW-DIAGRAM-INTEGRATION§acceptance-scenarios-O2 | Change graph membership or long-label content; placement adjusts without Causa-specific coordinate edits. |
| WORKFLOW-DIAGRAM-INTEGRATION§acceptance-scenarios-O3 | Render the same graph twice with the same engine/version/viewport; positions are stable within documented tolerances. |
| WORKFLOW-DIAGRAM-INTEGRATION§acceptance-scenarios-O4 | Verify that every causal assertion and evidence count in the graph matches the F# domain projection. |
| WORKFLOW-DIAGRAM-INTEGRATION§acceptance-scenarios-O5 | Exercise desktop, iPad portrait/landscape, mobile, keyboard, zoom, and text equivalent. |
| WORKFLOW-DIAGRAM-INTEGRATION§acceptance-scenarios-O6 | Verify that real GitHub-backed investigations use the same graph projection and layout integration. |
| WORKFLOW-DIAGRAM-INTEGRATION§acceptance-scenarios-O7 | Inspect the dependency and runtime evidence to confirm the existing engine was used, not reimplemented. |
| WORKFLOW-DIAGRAM-INTEGRATION§acceptance-scenarios-O8 | Run the controlled comparison and publish measured results, including token and implementation costs. |
